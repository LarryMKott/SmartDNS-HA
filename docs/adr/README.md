# 架构决策记录（ADR）

记录"为什么这样设计"，而不是"怎么用"。用法看 [docs/README.md](../README.md)，结构与不变量看 [architecture.md](../architecture.md)。

## 约定

- **一个决策一篇**，编号连续，文件名 `NNNN-短横线标题.md`。
- **已接受的 ADR 不修改结论**。决策被推翻时：新开一篇 ADR，把旧篇状态改为"已被 ADR-XXXX 取代"，并在旧篇顶部加链接。
- 每篇必须写清：背景、决策、后果（正/负）、备选方案及放弃原因、证据（代码/测试位置）。
- 状态取值：`提议` / `已接受` / `已废弃` / `已被 ADR-XXXX 取代`。

## 什么时候该写 ADR

- 选型：换了组件、协议、部署模型。
- 不可逆或高代价的决定：端口布局、数据目录、同步方向。
- 团队反复争论的问题：写下来，避免下次重新吵一遍。
- 明知有代价仍然选择的方案：把代价写清楚，比事后解释便宜。

不需要 ADR 的：改默认值、修 bug、加一个配置项（写进 [configuration.md](../configuration.md) 即可）。
